### The single-file executable is back, and the Log page no longer deletes keys it does not own

0.9.8 was a large release and it left the marks a large release leaves. This one adds no
features. It closes the holes 0.9.8 opened, resolves the places where the catalogue had
started contradicting itself, and puts the download back to the shape every release before
it had.

**Two files again.** 0.9.8 shipped neither of them. It was the first release cut by the new
workflow, and the workflow built against a *dynamic* Qt: the result was a 21 MB archive of
`Arbitrium.exe` plus every Qt DLL, two D3D compilers nothing in the app calls, and a stray
directory of CMake bookkeeping. Every release since 0.9.5 had been one 34 MB executable that
needed nothing beside it. Download **`Arbitrium-v0.9.9-win64.exe`** and run it; the `.zip`
holds that same file for anyone whose browser dislikes a bare `.exe`.

---

### The one worth reading about

**Undo on the Log page was deleting whole registry keys, including everything other tweaks
had written into them.**

When a journal line recorded that the value had not existed before the write, reverting it
called `RegDeleteTreeW` on the key — taking the key, every other value in it, and every
subkey. `keyExisted` is a snapshot from one instant, and these keys are shared: thirteen
catalogue tweaks write into `SOFTWARE\Policies\Microsoft\Windows\WindowsUpdate` alone.

So: apply *Take drivers from Windows Update* on a clean machine, then four more Windows
Update tweaks, then press **Geri al** on the first one. The entire Windows Update policy
subtree went with it — the other four tweaks' values, the `AU` subkey, and anything a domain
policy or another tool had put there in between. The row then said "geri alındı".

Undo now removes the one value it recorded. The key goes only if it is empty *at that
moment*, and only through `RegDeleteKeyExW`, which refuses a key that has subkeys — so even
a race cannot widen it back into a subtree delete.

Three more in the same area:

- **The journal was recording the state left by the tweak's own earlier writes.** "What was
  here before" was read inside the write loop, so entry *i* was captured after entries 0…i-1
  had already landed. About twenty tweaks put a `DELETE_KEY` on their first entry and keep
  the rest inside that same key — those journalled "there was nothing here" about values the
  app had just destroyed, which made them unrestorable. Every value a tweak owns is now read
  before any of them is written.
- **"Put it back the way this machine had it" did nothing until you restarted the app.** The
  map it reads from was built once at startup and never updated, so it always missed for a
  value first touched in the current session — which is exactly the flip-it-on, change-your-
  mind, flip-it-back case.
- **A migration step was deleting the current Take Ownership entry.** 0.9.3 moved the verb to
  `runas`; 0.9.5 moved it back to `ArbitriumTakeOwnership` — and the cleanup step was still
  deleting that name. Its guard was a flag in HKCU while the key it deleted is machine-wide.

### The twelve dashboard blocks 0.9.8 added, on a machine that is not in English

**Both PowerShell stages were being thrown away whole.** A GUI process starting
`powershell.exe` gets a console whose output code page is the system OEM one — 857 on a
Turkish install. One non-ASCII character anywhere in the answer (a disk's FriendlyName, a
Wi-Fi SSID, a localised `fsutil` line) reached Qt as a byte that is not valid UTF-8, and Qt's
JSON parser does not skip it: it fails the entire document. One character, and Inventory and
Hardware both returned nothing. The console is now put into UTF-8 explicitly, and the scripts
themselves are read as UTF-8 rather than Latin-1 — the `·` embedded in both was reaching
PowerShell as `Â·`.

With that fixed, the rows underneath it:

- **Blank rows now say "—".** The header promised every field started there; none of them did.
- **TPM ownership** was rendered and never filled in by anything.
- **DHCP** read "—" on every machine: `GetAdaptersAddresses` was called without
  `GAA_FLAG_INCLUDE_GATEWAYS`, so the gateway test rejected every adapter.
- **The two most common pending-restart flags could not be detected.** Windows creates them
  as *empty* keys and the code asked whether the key held anything. It also asked through
  QSettings, which opens keys with `RegCreateKeyEx` — looking for the flag risked setting it.
- **Third-party scheduled tasks** were undercounted about five to one: tasks at the root path
  were excluded, and that is where installers put theirs.
- **Battery health said "Yok" on machines with a battery** when the WMI classes simply were
  not exposed.
- **The page mixed GiB with GB**, and the **time zone was an hour out for half the year**
  (`DaylightBias` was added whether or not daylight time was in effect) and truncated
  half-hour zones — India read as UTC+5.
- **Logical cores** were counted in the current processor group only, while physical cores
  were counted across all of them.

### Ten languages, and what was still in one

**Switching language translated the labels and left every value in the old language.** Both
fact structs hold finished sentences — "Açık", "Şebeke", a date written the way the locale
writes dates — so re-pushing the same struct changes nothing. `SysInfo` is now re-read, and
`DeepInfo` rebuilds from the JSON its two PowerShell stages already returned, so it does not
pay for them twice.

- **Twenty-eight service risk notes** ("Yazdırma ve tarayıcı kuyruğu tamamen durur") were
  Turkish literals in a table, shown untranslated in the other nine languages.
- **The percent sign was on the wrong side in nine languages.** `%%1` is not an escape in Qt;
  the Turkish convention had been copied verbatim.
- **The Settings language row was telling you something that stopped being true in 0.9.8** —
  that tweak names and descriptions are Turkish only.
- Typing `%2` into the search box corrupted the results header.
- Arabic is now drawn with an explicit text direction, so punctuation at the edge of a line
  lands on the correct side. Mirroring the layout itself is a separate job and is not in this
  release.

### Settings and controls that did nothing

- **"Compact rows" had no listener anywhere in the app.** The switch wrote the setting and
  emitted its signal into the void; rows kept their height until the next launch.
- **"Check for updates on launch" opened a browser by itself**, seconds after the window
  appeared. Its own description says it looks *silently*.
- **Escape never reached the apply overlay** — a window shortcut consumes the key before any
  widget sees it — so the overlay could not be dismissed from the keyboard, and Escape during
  a run cleared the search box behind the scrim.
- **The overlay's 160 ms fade-out never drew a frame**, and the overlay did not follow the
  window when it was resized mid-write.
- **The Services and Startup section headings rendered blank** in every language.
- **Pressing the number beside a range slider jumped the value to maximum.**
- Command-line switches were one-shot in name only: `--accent` to try a colour wrote it to
  your saved settings permanently, and `--theme` read as "light, or else dark", so any
  misspelling silently meant dark.

### The catalogue: 411 → 391

0.9.8's 143 new tweaks collided with existing ones in seventeen places — two rows owning the
same registry value, so whichever you flipped last won and the other showed the wrong state.
In each pair the row covering more of the value stayed; where they were equivalent the older
id stayed, because presets and journal entries in the wild name it. `wu-WPFTweaksRazerBlock`'s
one unique value moved into `upd-drivers`, so nothing was lost.

Three more went because they could not work as written: `net-nagle` wrote to the `Interfaces`
container instead of the per-adapter subkeys under it (and then read its own write back as
proof it had worked); `wu-WPFToggleHideSettingsHome` wrote `show:home`, which
`SettingsPageVisibility` does not parse, and installed a live policy in its *off* position;
`upd-no-auto` was a second owner of a value `upd-auoptions` already expresses as a position.

Also: the three mouse-acceleration values and the Sticky Keys flag were declared `DWORD` when
Windows stores all four as `REG_SZ`, so applying them rewrote the value's type; and
`wu-WPFToggleStartMenuRecommendations` installed three policies in the position the whole app
treats as "what Windows ships".

---

### Elsewhere

Removing an app reported success whatever happened — every requested package was counted as
removed and the errors were silenced, so PowerShell exited 0 too. Each package is now checked
against both the registered and the provisioned list, and anything Windows kept is named. The
Ultimate Performance actions looked the plan up by its English name and did nothing on a
Turkish install. About 15% of the service list was per-logon instances that vanish on the next
reboot. `takeown` and `icacls` output was decoded with the wrong code page. An action that
failed to launch left its row reading "çalışıyor" for good.

The release workflow itself now builds against a static Qt, reads the finished executable's
import table back with `objdump` and fails if Qt or the MinGW runtime appears in it, and
creates the release *after* the build rather than before — which is precisely how 0.9.8 came
to exist with the wrong payload and no error anywhere. `workflow_dispatch` takes a `dry_run`
input that builds and checks everything and publishes nothing.

The full list, including the dead code removed and the duplication folded together, is in
[CHANGELOG.md](https://github.com/shadesofdeath/Arbitrium/blob/main/CHANGELOG.md).
