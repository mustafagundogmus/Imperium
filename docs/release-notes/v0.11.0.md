### It updates itself now, the Overview has icons, and Settings is a screen somebody designed

0.10.0 shipped yesterday. This one is about the parts of the application you look at.

---

### Arbitrium updates itself

When there is a new version, it asks at launch. Say yes and it downloads it, checks it, puts it in
place and restarts into it. Nothing about the portable promise changes: no installer, no service,
no scheduled task, nothing left in the folder but the one file you already had.

The header of `updater.h` used to say the check "never downloads or installs anything — it hands
the user the release page and lets them decide." That is no longer true, so it has been rewritten
to say what the code actually does. The rule that replaced it is the one that matters:
**nothing happens until a person says so.** The launch check only looks; the only thing that
downloads or replaces anything is the button in the offer.

The download is checked against the `.sha256` the release publishes, and if it does not match,
nothing is executed. What you are shown says plainly what that proves and what it does not: it
proves the file arrived whole and is the one that release published; it is **not** evidence about
who built it, because anyone who could replace the executable could replace the sums file in the
same motion. The thing that proves origin is the build attestation GitHub publishes, and verifying
a Sigstore bundle in-process is not something to attempt inside a tweaking tool — the comment says
so and points at the `gh attestation verify` command the README already documents.

Windows will not let a running executable be overwritten, but it will let it be renamed. The new
version lands beside the running one, is verified, the running file is moved aside, the new one
takes its place, it starts, and the old process exits. The leftover is swept on the next launch —
which is expected to fail on the first try, because the process being replaced may still be
exiting, and the second attempt a few seconds later is the one that lands.

A folder that cannot be written to is detected **before** anything is downloaded rather than at the
end. Every failure names the stage it stopped at and leaves you with a working application — with
one exception, the branch where the new file could not be put in place *and* the old one could not
be moved back. That branch exists, so instead of pretending otherwise the message tells you where
your application is and what to rename it to. The header says the same thing rather than hiding it.

**The launch check is now on by default.** Off, the whole feature was dead for anyone who never
went looking for the button — and a copy of a program that runs elevated and writes to the registry,
sitting three versions behind, is a real cost rather than a neutral one. What makes that defensible
is what the check is: one anonymous GET to `api.github.com` carrying a User-Agent and nothing else —
no identifier, no machine facts, no telemetry of any kind — held to once a day. The switch in
Settings turns it off in one click and its description says exactly what it does.

### Icons on the Overview cards

Twenty-nine cards now carry an icon beside their title, from **lucide**, fetched at authoring time
and compiled into `src/icons.cpp` as path data. Nothing is fetched at run time: this is a portable
executable and it has to work offline.

They go through the renderer the application already had, so theme, accent, text size and
fractional device pixel ratios were solved before they arrived — no second mechanism was added.
The stroke is 1.75 of lucide's 24 units rather than its native 2, which at the 14px box a card title
asks for lands on 1.02 logical pixels: the same hairline as the eight glyphs that were drawn by
hand for this app, so they do not read as borrowed.

Every card title was measured in all ten languages at the 1240px minimum window — the tightest is
Russian *"Программное обеспечение"* at 165px in 274px of room — and nothing elides because of an
icon. lucide's ISC licence is in `resources/licenses/`, and the release zip now carries nine
licence files.

### Settings

The complaint was that it felt cramped and jumbled, and measuring it found the cause: **four
galleries were being worn as the trailing control of a list row.** `SettingRow::Trailing` was built
for a 30×16 toggle or a ghost pill, and it was being handed a 372×158 theme grid, ten language
chips, six typeface specimens and eight accent swatches.

Two things followed. Row heights of 158, 58, 27, 22 and 40 pixels in one list joined by a single
pixel — and since the rows draw no rule and no background, the only thing separating one setting
from the next is padding, which against a 158px row is no signal at all. And the widest control took
the column from the longest caption: the language description is 1136px of French at the default
text size and was being given 164 of the 970 available. That stub was the most cramped-looking thing
on the screen.

A new arrangement, `SettingRow::Below`, gives the caption the full column and puts the control on
its own line under it, and all four galleries now follow one rule: uniform cells, one 10px gap, and
a wrap that rebalances its rows. At 1240×760 that puts **all ten languages on one line** at every
text size and **all eight themes in one row**.

The grouping was redone by where you would look for something rather than by when it was added, on
the rule of one shape per section: **Görünüm** is now the five settings that offer a choice from a
set, and a new **Arayüz** section holds the three on/off switches. Language moved to the top,
because somebody who has landed in a language they cannot read has to find it *without reading*,
and the ten native names are legible whatever is in force.

Two bugs turned up on the way. `TypefacePicker` had no `typefaceChanged` connection at all and built
its specimens bypassing `Theme::font()` — it was the one control on the page that stayed at 1.0 size
when everything else grew. And `SettingRow` was not repositioning a trailing control after a font
change, so a pill that got wider stayed where the narrower one had been.

The theme description was also stale: it named four palettes and there are eight. Corrected in all
ten languages.

### The About page

It was four bare rows. It is now two of the Overview grid's own cards — the same `InfoSection`,
not a new component that would look almost like it — and every figure in them is read back out of
the running build: version, Qt, licence, the size of the catalogue and the number of actions, then
the count of themes, accents, languages, typefaces and text sizes. The page cannot advertise a
language or a typeface this executable does not carry.

Four of those five counts come straight off the table that defines them. The themes could not:
a C++ enum has no count, so `Theme::AppearanceCount` was added beside it with a `static_assert` that
fires wherever a ninth palette is inserted. All four links still work and the donation row is still
last and still plain.

---

### And the scrollbar is thicker

8 pixels to 12. The handle is inset by a 2px border on each side, so 8 left a 4px strip to grab.
The sidebar measures its rows against this number in a two-pass resize, so the arithmetic there was
re-checked rather than assumed.
