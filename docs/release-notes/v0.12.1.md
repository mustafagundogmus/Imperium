### The overview was writing to the registry, and twenty-four catalogue rows were wrong

A fix release. Nothing new to click; a fair amount that now does what its label says. It
came out of a full read of the source and of every row in `catalog.json` against what
Windows actually reads.

---

### Reading the machine was creating registry keys

`sysinfo.h` says "nothing is written". That was not true. Every bulk read of a key went
through `QSettings`, and `QSettings` opens a registry path with `RegCreateKeyEx`: pointing
it at a key that is not there *creates* the key. The Overview reads a dozen keys whose
absence is the ordinary state of a machine — `SecureBoot\State` on a BIOS boot, the
`DataCollection` and `System` policy keys on an unmanaged PC, the `vmms` service where
Hyper-V is not installed, a ProgId under HKCR — and every launch was leaving empty keys
behind in HKLM. A script that tests for `SecureBoot\State` to decide "is this UEFI" would
have started saying yes on a BIOS machine that had run Arbitrium once.

`Registry::openKey` now asks `RegOpenKeyEx` first, which creates nothing, and answers an
absent key with an empty, file-less store. Every value reads as absent; nothing on the
machine changes.

---

### Three programs still started by bare name

0.12.0 closed the "bare program name resolved through an inherited `PATH`, inside an
administrator token" hole for PowerShell, and said so. Three launches were missed: the Apps
page's scan (`powershell.exe`), the take-ownership shell verbs (`takeown.exe`, `icacls.exe`)
and the System Protection button (`SystemPropertiesProtection.exe`). All three now run from
System32 by absolute path, through the same `winpaths.h` the rest of the app uses.

---

### Precision touchpads scrolled nothing

A precision touchpad and a free-spinning wheel deliver wheel deltas well under the 120 of a
notch. The smooth-scroll path computed `delta / 120 * step`, which is zero for every one of
them, accepted the event, and left the page where it was. Smooth scrolling is on by default,
so on those devices no page scrolled at all — until the setting was switched off, which
routed the event to Qt's own handler. The remainder is now carried from one event to the
next, so a notch's worth of small deltas adds up to one notch.

---

### The dialog scrim covered the shadow margin

The dialog sized its scrim to the *window*, and the window's rectangle includes the
transparent margin the drop shadow is painted in. Every confirmation painted a hard-edged,
near-opaque rectangle past the card on all four sides, over the desktop. It is sized to the
card now. Toggling Details also no longer snaps a dialog you had dragged back to the corner.

---

### Overview values that were simply wrong

- **Boot duration** read property 0 of event 100, which is `BootTsVersion` — the constant 2 —
  and showed "0.0 s" on every machine that had the event. Property 5 is `BootTime`.
- **Idle time** subtracted the 32-bit `LASTINPUTINFO::dwTime` from the 64-bit
  `GetTickCount64()`. Past 49.7 days of uptime the row read about seventy thousand minutes.
- **Pending domain join** was looked for as a value of the Netlogon key. `JoinDomain` and
  `AvoidSpnSet` are subkeys; the reason could never fire.
- **Wi-Fi signal** was matched on the label "Signal", which `netsh` prints in the display
  language. The percentage is now picked out by its shape.
- **IPv4 gateway** was read from the first gateway entry only; on a dual-stack link that is
  often the IPv6 router, and the row showed "—". The **IPv6 address** shown was usually the
  link-local `fe80::` one; a routable address is preferred now.
- **The percent sign** was hard-coded in the Turkish position (before the number) in three
  places — DPI scale, battery, commit charge — so nine languages read "%150". It goes
  through the translation table like the battery-health row already did.

---

### Smaller ones

- The apply overlay blocked the mouse but not the keyboard: Tab moved focus to a switch
  under the scrim, and Ctrl+K reached the search box, mid-write. Both are held now.
- The overlay's "current item" line showed the raw Turkish name in every language; it goes
  through `displayName()` like everything else.
- The TrustedInstaller launcher leaked its attribute list when `UpdateProcThreadAttribute`
  failed.
- `.reg` export: BINARY bytes were not put through the canonical two-digit spelling, and a
  MULTI_SZ was missing the second null that closes the list.
- The Apps page's Remove button stayed where it was after a typeface or text-size change.

---

### The catalogue: rows that wrote the wrong thing

Each of these was checked against what Windows reads, not against what the row said.

- **gt-lockscreen-timeout** — on and off were inverted. For a power setting, `Attributes`
  1 hides it and 2 shows it; the row that promised to unhide the setting was hiding it.
- **ch-launchto** — "Home" wrote 3, which is Downloads. Home is 2, This PC is 1, Downloads
  is 3, and the row now offers exactly those three.
- **aud-ducking** — the value map was shifted by one: 0 mutes, 1 is 80 %, 2 is 50 %, 3 does
  nothing. The default is 80 %, not "do nothing".
- **cln-do-cache-age** — `DOMaxCacheAge` is in **seconds**. A slider labelled 1–30 days
  wrote 1–30 seconds and emptied the Delivery Optimization cache almost immediately. It is
  a choice of days now, with "Default" meaning not configured.
- **cln-do-cache-size** — wrote `DOPercentageMaxForegroundBandwidth`, a bandwidth cap;
  setting it to 50 throttled update downloads to half speed. The cache-size policy is
  `DOMaxCacheSize`, default 20 %.
- **pwr-update-wake** — `AUPowerManagement` lives under `WindowsUpdate\AU`, one level
  below where it was written.
- **sec-smartscreen-apps** — `SmartScreenEnabled` (Warn / Block / Off) is read from the
  Explorer key, not from `Policies\System`.
- **wu-WPFTweaksRevertStartMenu** — `ControlSet001` is not always the live control set;
  `CurrentControlSet` is.
- **wu-WPFToggleHiddenFiles** — Explorer writes 2 for "don't show", not 0.
- **cln-shutdown-app-timeout** — the Windows default is 20000, not 5000.
- **cln-evt-autobackup** — `AutoBackupLogFiles` only takes effect with
  `Retention = 0xFFFFFFFF` on the same key; both logs now get it.
- **ctx-runas-user** — `runas.exe /netonly /user:%%USERNAME%%` could never work: a REG_SZ
  verb does not expand environment strings, and `/netonly` runs the program as the current
  user anyway. Windows already has this verb, hidden behind Shift+right-click; the row now
  removes its `Extended` mark instead.
- **wu-WPFTweaksHiber** — wrote `HibernateEnabled` under `Session Manager\Power`, where it
  is not read; the value lives in `Control\Power`, where `pwr-hibernate-file` already writes
  it. The row keeps its other half and is named for it: hide the Hibernate menu entry.
- **sec-lm-hash, sys-04-2688, priv-01-4010, priv-02-4013, net-02-3286,
  wu-WPFToggleNewOutlook** — the "off" position wrote a *configured* policy value (in
  `sec-lm-hash`'s case, one that enables LM hash storage). Off now removes the value.
- **ch-taskbar-size** — `TaskbarSi` stopped working in 22H2; `maxBuild` is 22000.
  **net-02-19242** and **adv-02-29115** are 24H2 features; `minBuild` 26100.
- **sec-smb1-client** — the description now warns: if `mrxsmb10` is listed among the
  Workstation service's dependencies, disabling it stops that service at the next boot, and
  every network share with it. Removing the SMBv1 client through Windows Features is safer.

### Rows whose name said something else

- **perf-memory-compression** → **Page combining**. `DisablePagingCombining` is page
  combining, not memory compression.
- **aud-exclusive-mode** → **Protected audio path (DRM)**. `DisableProtectedAudioDG` is the
  protected audio graph; exclusive mode is a per-endpoint property.
- **pwr-sleep-button** → **Unattended sleep timeout setting**. GUID `7bc4a2f9-…` is "System
  unattended sleep timeout", nothing to do with the Start menu's Sleep entry.
- **pwr-adaptive-brightness** — the row unhides the setting; the description said it turned
  adaptive brightness off.

### Removed

- **net-autotuning** — there is no `TcpAutotuning` parameter under `Tcpip\Parameters`; the
  receive-window level is a `netsh` setting held in the NSI store.
- **wu-WPFToggleStandbyFix** — a power policy under HKCU is never read; `net-02-3286` holds
  the same GUID under HKLM.
- **pwr-pcie-aspm**, **pwr-lid-close** — `Attributes` only controls whether a power setting
  is shown, and both of these are shown by default. The rows could do nothing.

The catalogue goes from 411 rows to 407. Presets naming a removed id are skipped and
counted, as they always were.

### Actions

- **act-disk-cleanup** — `cleanmgr` is a GUI program; the script did not wait for it, so
  DISM ran underneath it, and the drive was a hard-coded `C:`.
- **act-svchost-threshold** — on a virtual machine that reports no `Win32_PhysicalMemory`
  the threshold was written as 0; it falls back to `Win32_ComputerSystem`.
- **act-remove-edge** — `${Env:ProgramFiles(x86)}` spelled the way PowerShell means it.
