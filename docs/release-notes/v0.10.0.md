### Two new tools, an open-source licence, and a release you can check for yourself

The version jumps to 0.10.0 because this is the first release that adds pages rather than
settings — and because a lot of what changed underneath is about being able to prove what the
app does rather than asking you to believe it.

Arbitrium is now **MIT licensed**. It had been public for thirty-one commits without a licence
file, which meant that whatever the badge said, nobody had permission to use, modify or
redistribute any of it. That is fixed, at the root, where GitHub can see it.

---

### God Mode — search Windows' own settings

A new page: thirty-eight shortcuts in eight groups — Windows settings pages, Control Panel
applets and management consoles — with a search box over them and, under every row, the exact
thing it opens. The row that opens Windows' own "All Tasks" folder, the one people call God
Mode, is there too.

The page changes nothing on your machine. It opens Windows' own window and that is all it does.
The list lives in `resources/data/settings-links.json` and is read **only from the compiled
resource**, under the same rule as the tweak catalogue: a file left beside the executable cannot
redirect what an elevated process opens.

All twenty-five `ms-settings:` targets were checked against the 268 URIs Windows' own
`SystemSettings.dll` declares, rather than against anybody's memory. Consoles and applets launch
through `mmc.exe` and `control.exe` by **absolute path** out of System32 — never a bare name,
which in an elevated process means trusting an inherited `PATH`; this is the same class of
problem already fixed for `tbs.dll` and `netapi32.dll`. `explorer.exe` and `regedit.exe` are in
`C:\Windows` rather than System32, so the resolver looks in both. A target that is not on your
machine — `gpedit.msc` on Home, for instance — is drawn dimmed with the reason, instead of
failing after you click it.

`tools/check-data.py` gained a check for all of this: every id needs its label in ten languages,
ids must be unique, and a target may not carry a path of its own, since `..\Temp\x.exe` would
quietly make the System32 guarantee meaningless.

### Advanced restart

Six new entries on the Actions page: restart, **Advanced Startup** (the WinRE recovery menu),
straight into **UEFI/BIOS** setup, **Safe Mode**, **Safe Mode with networking**, and **clear the
Safe Mode setting**.

Not a new page — data. The Actions page already shows an action's exact script in full before it
runs and runs it only on confirm, and "read what will run, then decide" is precisely the contract
these commands need.

Safe Mode is **sticky**, and the note says so in capitals: `bcdedit` writes it into the boot
configuration, so the machine keeps starting in Safe Mode until the setting is cleared. The way
out is on the same page and named in the warning. The `$LASTEXITCODE` check sits **between**
`bcdedit` and `shutdown`, which is the whole point of that pair — restarting after a `bcdedit`
that was refused is the worst outcome this change could have: the machine goes down, comes back
exactly as it was, and you believe you are in Safe Mode. The UEFI entry stops with an error on a
legacy BIOS machine rather than restarting into Windows and leaving you wondering.

### Presets carry your appearance and settings, and only what you changed

The preset format is version 3, with two optional blocks: `<appearance>` (theme, accent,
typeface, text size, density, interface language) and `<settings>` (smooth scrolling, border
glow, update check at launch, confirm before apply). Version 1 and version 2 files still load
exactly as they did.

Export no longer writes every id in the catalogue. It used to write 706 of them on a normal
machine — 390 catalogued tweaks plus the 307 services and 9 startup entries synthesised from the
live machine — so a file you thought of as "my forty tweaks" was seven hundred lines and carried
machine A's entire service configuration onto machine B. Now it writes what you actually moved.

Import still only **queues** tweak positions: nothing is written until you press Apply, and this
change does not touch that promise. Appearance and settings are the app's own preferences and
take effect immediately, so when a file carries them you are asked once, with two buttons.
Whichever you press, the tweaks are queued. A theme or typeface name this build does not know —
from a newer version — is ignored rather than resetting yours, because an unknown value should
never behave worse than an absent one.

### Restarting Explorer now works on Windows 10

Some tweaks only take effect once the shell re-reads the registry. On Windows 11 killing Explorer
brought it back by itself; on Windows 10 it stayed dead, and you were left with no desktop and no
taskbar.

The cause is subtler than it looks. Arbitrium always runs elevated, so
`startDetached("explorer.exe")` asked for an elevated Explorer — and Explorer will not be the
shell with that token. It does not simply give up, though: it hands the job to a scheduled task
called `CreateExplorerShellUnelevatedTask`, which starts it again as you. That task is created on
demand the first time Explorer is launched elevated, so it can be missing, disabled, or pruned by
exactly the sort of debloating this app does. The failure was conditional, which is why it showed
up on other people's machines and not on the developer's.

`Shell::restartExplorer()` is rewritten around checking rather than around doing:

* The shell is **asked to exit** first — the request the hidden "Exit Explorer" item makes — so it
  saves the desktop layout, the taskbar's state, and the icon and thumbnail databases it holds
  open. It is terminated only if it will not go, and then **only that one process**: the old
  `taskkill /F /IM explorer.exe` matched by name across the whole machine and took a second
  signed-in user's shell down with it.
* It comes back **unelevated**, created with an ordinary process in your session named as its
  parent so it inherits that token instead of ours.
* The result is **verified**. `GetShellWindow()` is polled for a bounded time and success is
  reported only when a shell actually holds the desktop. No branch reports a success it has not
  looked at.

When it fails, the error names the stage — and if you have genuinely been left without a desktop,
how to get one back from Task Manager. The three actions that used to stop the shell themselves no
longer do, for the same reason; `shell.cpp` is the only place that touches Explorer now.

### Fixes

**Service rows could write a `Start` value you did not choose.** `Tweak::literal` exists for rows
whose default position came off this machine rather than out of Windows; startup entries set it,
services did not, though they derive their default the same way. So a service disabled in one
session, then moved to Auto and back to Disabled in the next, had the engine write the `Start` the
journal remembered instead of the one the row asked for — the service stayed on Auto while the row
and the applied count both said Disabled. One line, and the largest group of rows in the
catalogue. `AppState::applyOne()` now also reads the machine back after a successful write, so the
session agrees with what the next launch will show.

**Actions reported failure as success.** Every script ends by printing its own result line with
`Write-Output`, which is a cmdlet and always succeeds, so an action whose real work failed still
reached that line and still exited 0. The generated script now starts with
`$ErrorActionPreference = 'Stop'`; lines meant to fail quietly already say so themselves with
`-ErrorAction SilentlyContinue`, and a parameter beats the preference. The two native tools that
had no exit-code check got one — DISM's 3010 means "done, restart needed" and is accepted;
`cleanmgr`'s code is deliberately not read, and the script says why. `act-store-search` had the
plainest version of the bug: its report sat on the same line as the command, after a semicolon, so
it printed whether or not `icacls` had done anything.

**Action output was decoded with the wrong code page.** Console programs write to a pipe in the
*console* code page while Qt read it back with the ANSI one, so every non-ASCII byte from DISM,
`cleanmgr` or `icacls` arrived wrong in the panel and in `actions.log`. The decoder that
`ownership.cpp` had already worked out for itself now lives in `src/console.h` and both callers
use it.

**`act-block-adobe` appended the list twice if you ran it twice.** It now takes only host lines out
of the download and writes them between its own markers, replacing that block whole — and a new
action removes exactly that block, so it is reversible.

**A tweak that wrote a value from a different subsystem is gone.** `sec-powershell-v2` was called
"PowerShell 2.0 engine" and wrote the value behind the execution policy's MachinePolicy scope,
which is inert without its companion. The PowerShell 2.0 engine has no registry switch; it is a
Windows optional feature. Of 391 rows it was the only one whose text and whose written value
belonged to different subsystems.

**The README said the app creates a restore point.** It does not, deliberately — it opens Windows'
own System Protection window, because creating a point changes the system and this build writes
nothing you did not ask for. The in-app text had been honest all along.

### Under the hood

**Every commit is compiled now.** `.github/workflows/ci.yml` builds on every push and pull request
and runs the data check, in about two minutes. Until now the first machine to compile a commit was
the machine cutting a release, and the cost of that is written into the history between 0.9.9 and
0.9.10: eleven commits in a row that did nothing but fix the build.

**`tools/check-data.py`** validates the three data files with no compiler and no Qt, in 70ms. Ten
checks, and it reads the schema out of the source rather than restating it — the language list, the
hive spellings and the risky-service table all come from the C++. The one that matters most: when
an option's data array is shorter than its `reg` array, the parser pads it and Registry reads that
back as a silent DWORD 0 written to a real key.

**`-Wall -Wextra -Wshadow` are on in the build.** Measured across all twenty thousand lines: zero
warnings. That state was being maintained by hand; now it is maintained by the compiler.

**The published files prove where they came from.** Every release asset now carries a build
provenance attestation binding its digest to this repository, the commit and the workflow run, and
`gh attestation verify` checks it without a key from anyone. A `.sha256` goes up beside them, with
what it is worth written down plainly: it catches a truncated download and nothing else. The
executable is still unsigned, and the README now says what happens when you run it, what
SmartScreen will show you, and what you can check instead of taking anyone's word.

`contents: write` moved to the publish job alone, the Qt source tarballs are verified against
digests recorded in the repository before they are unpacked, and the tag shape check is an anchored
regex rather than a glob that matched anything after the last digit. The third-party licences —
LGPL-3.0 and GPL-3.0 for Qt, the SIL OFL for all six bundled typefaces — now travel inside the zip
instead of only in the repository.

**Tweak rows tell a screen reader what they are.** Nothing in a row is a stock widget, so it was an
unnamed rectangle containing an unnamed control; `setAccessibleName` appeared nowhere in the source
at all.
