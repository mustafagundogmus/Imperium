### It draws its own dialogs now — and the launch that took thirty seconds does not

Three people reported the same thing in different words: it opens instantly for some and
hangs for others, and one of them waited half a minute watching a spinner. That is the
first thing in this release, and finding it turned up two more faults behind it.

---

### The thirty-second launch

`QStandardPaths::findExecutable("powershell")` does not merely trust `PATH` — it **walks**
it, stat-ing a candidate in every entry until one answers. A machine whose `PATH` holds a
mapped drive that is no longer reachable therefore blocks for the SMB timeout. It was
called twice, both times on the UI thread, before the window could paint.

On a machine whose `PATH` is all local it costs nothing measurable. That is exactly why it
reached users and never the developer: on this machine the whole of `SysInfo::collect()`
measures **3.7 ms**, and the three CIM queries behind the Overview total 786 ms.

`ActionEngine` had the same hole in a worse place. It passed the bare name `powershell.exe`
to `QProcess`, which resolves it against `PATH` — in a process running as administrator,
for a program about to be handed a script to run.

All three are the same class of fault this project already fixed for `mmc.exe`,
`control.exe`, `tbs.dll` and `netapi32.dll`; these three were simply missed. A new
`src/winpaths.{h,cpp}` asks `GetSystemDirectoryW` for System32 — which cannot be lied to by
an inherited environment block — and resolves PowerShell at its fixed absolute path. When
it is not there, the action fails with a message rather than falling back to whatever
`PATH` offers. `godmodepage.cpp`'s identical second copy of that resolver is gone.

**An honest limit:** this could not be reproduced here. The diagnosis comes from the code
and from measuring everything else on the startup path, not from a machine that stalls. The
next item is what turns the next report into evidence.

---

### The splash was frozen, not slow

`splashscreen.h` said "the splash paints, the main window is built behind it." That was not
true. Nothing pumped the event loop between `show()` and `finish()`, so the card painted
exactly once and then sat frozen for however long the constructor took. On a slow machine
what the user saw was not a slow application — it was a hung one.

`Splash::report()` fixes both halves. The startup work names five stages and each call
repaints the card and gives the loop a turn:

**Katalog okunuyor → Hizmetler taranıyor → Sistem bilgileri okunuyor → Arayüz hazırlanıyor
→ Ayarların durumu okunuyor**

So the animation runs, and the bottom line of the card says which stage is in progress.
Anyone whose machine stalls can now say *where* it stalled from a screenshot — no debug
build, no log file. The service scan is named separately from the catalogue because it is
the stage most likely to be slow on someone else's computer.

---

### The application's own message box

`QMessageBox` was the one surface in the app that the app did not draw. It brought Windows'
window frame, Windows' title bar, its own grey, its own button metrics and its own font. In
a frameless, themed, ten-language application it read as a different program interrupting
this one — and it could not follow the theme, so on the light palettes it stayed whatever
the system said.

The new `Dialog` is that box in the design's own vocabulary: the `ApplyOverlay` card, on the
same scrim, at the same radius; `Font::blockTitle()` for the heading; the body **wrapped
rather than elided**, because a dialog is the one place the text has to be read in full; and
`PillButton::Accent` / `Ghost` for the answers.

The detail panel is better than the one it replaces. An action's whole script sits in an
inset monospace panel that can be **selected and copied** — which `QMessageBox`'s own detail
box never allowed, in the one block whose entire purpose is that it can be checked against
something else.

It snaps to a whole number of lines. That rule took three attempts: the cap is a pixel
count and the line height is a font metric, and at the mono face's 22px line a nine-line
script wants 202 against a cap of 200 — so the panel showed eight lines and the top half of
a ninth. A half line reads as a rendering fault, not as "there is more". The row height now
comes from `QPlainTextDocumentLayout::blockBoundingRect()`, the thing that actually places
each block; `fontMetrics().lineSpacing()` was a pixel short of it, which is a whole line
over nine of them.

Escape and a click on the scrim decline, Return accepts, the card drags. All eight call
sites are converted and no `QMessageBox` remains in the source.

### Twenty-three tweaks, and four that were wrong

The catalogue goes from 390 rows to 411. Recall removal, the five app-inventory collectors
24H2 introduced, cross-device clipboard, OneSettings, memory contents in a crash report,
the NCSI probe, the hidden `C$`/`ADMIN$` shares, lock-screen widgets, the Copilot key's
target, `sudo` mode, the periodic registry backup, and more.

Two rules were applied to all of them. **The name describes the effect, not the mechanism** —
"OneSettings indirmeleri" became **"Windows'un kendini uzaktan ayarlaması"**. And **a row
with a cost opens with the cost**: the Recall row begins "the snapshots stored on disk are
deleted and do not come back", the registry-backup row begins "an unencrypted copy of the
SAM and SECURITY hives sits on disk".

Four existing rows were defective:

**`perf-game-mmcss` wrote four values; three of them do nothing.** Microsoft's own MMCSS
page marks `GPU Priority` and `SFIO Priority` as not used, and says `Priority` is treated as
2 regardless in the High category. The row also wrote `GPU Priority` as `off='8' on='8'` — a
no-op against its own data even if the kernel read it. Only the one value that is genuinely
read remains.

**`perf-vrr` and `perf-autohdr` are removed.** Both were *tokens inside a single REG_SZ*:
`DirectXUserGlobalSettings`, in the form `AutoHDREnable=1;VRROptimizeEnable=1;`.
`perf-autohdr` mistook a token payload for a value name and wrote a value called
`AutoHDREnable`, which Windows never reads. `perf-vrr` targeted the right value but wrote
its whole string, silently erasing every other token — including `HighPerfAdapter`, the
preferred-GPU choice, on exactly the multi-GPU laptops that care about VRR. The catalogue's
`reg` shape has no read-modify-write, so the row cannot be made correct; this is the same
verdict `sec-powershell-v2` got. Both toggles live in Settings › System › Display ›
Graphics, where Windows keeps this value authoritative.

**`perf-hpet-timer` had the right value and the wrong description.** It is not a platform
timer or an HPET setting: it removes the per-process isolation Windows 10 2004 introduced,
so one application calling `timeBeginPeriod` speeds up the whole machine's timer.

### Four more light themes, and twelve palettes that were measured

There were eight schemes and only two were light. Now there are twelve and six are: **Sis**
(dimmed), **Yüksek karşıtlık** (AAA, 7:1), **Çayır** and **Leylak**. Four rather than three,
because twelve divides evenly by every column count `flexColumns` can land on — 12, 6, 4, 3,
2 and 1 — while eleven would leave a ragged last row at four of its six shapes.

Then the palettes were measured, and the file did not hold its own claim. Light's
`textFainter` was **2.18:1** and Sepia's **2.20:1** against a documented 4.5. Three *dark*
schemes missed it too, on the same token and the same ground: Dark's documented 4.52 is its
window figure, and on the `#1B1B20` overview tile the same grey is 4.34.

Every text token is now measured **on the surface it is actually painted on**, traced to the
widget that fills behind each label rather than assumed — and three rows of the table the
newest schemes carried were wrong (`iconStroke`, `textMono`, `textMuted`). Only text colours
moved: surfaces, borders, toggles and `scrollThumb` are byte-identical. The five schemes
that had no checkable figure gained 55 annotations, so all twelve can be verified rather
than trusted.

`accentInk()` also resolves to each scheme's own floor now. Its floor was a hardcoded 4.5,
so the Contrast scheme promised AAA while drawing the selected category label — real body
text — in an ink between 4.55 and 5.92.

### A hole in the data check

`tools/check-data.py` passed green with **forty-six translation keys missing**. Check 8
walks `src/` for literals and exempts `tweak.` as a runtime prefix; check 6 verifies that the
keys i18n.json *has* are filled in for all ten languages, which says nothing about a key it
does not have. Twenty-three rows would have shipped Turkish in nine languages with every
check on the page green.

**Check 12** now requires a key for every catalogue row and for every option label carrying a
word — three letters or more, so "50 MB" and "22H2" need none and "5 saniye" does. Which
caught a second fault: `displayLabel()` returned digit-leading labels verbatim, a rule
written for range sliders that also swallowed the new duration choices.

Twenty-five rows were translated into ten languages, including the two repaired ones — whose
English text still carried the claim the repair had removed.
