### Launch anything as TrustedInstaller, eight themes, and the nine regressions 0.9.9 introduced

0.9.9 was a large bug-fix release, and a change that big leaves its own marks. This one adds
a tool and a set of themes — and closes nine regressions the 0.9.9 diff introduced while
fixing the older ones. Those were found by putting the 0.9.9 change itself through the same
adversarial review the release notes describe; the fixes are below.

---

### Launch anything as TrustedInstaller

A new tab in the sidebar, under Actions. TrustedInstaller is the account Windows keeps for
servicing itself — the owner of the files and registry keys even an administrator is refused
until they take ownership first (which is what the Take Ownership feature does, one path at a
time). Point the page at a program or a file, or use the one-tap shortcuts for a shell,
PowerShell, the registry editor, or the file manager, and it starts under that account, able
to read and write all of it without changing a single permission.

The launch is native — `src/trustedinstaller.*`, not a script. It starts the TrustedInstaller
service, then creates the new process with the TrustedInstaller process named as its **parent**,
so the child inherits its primary token, the technique NSudo and PowerRun use. Nothing is
written to the machine to make this work; it is possible only because the app already runs
elevated, and a standard token cannot reach the account by any means. An executable runs
directly; anything else — a script, a document, an installer — opens through the shell in its
associated handler, also as TrustedInstaller. `whoami` in the launched shell says
`nt service\trustedinstaller`, which is the whole test. The page dims and says why when the app
is not elevated, and every string is in ten languages.

### Eight themes

Appearance went from dark/light to eight palettes. The two shipping ones are unchanged; six
are new:

- **Midnight** — a near-black, higher-contrast dark, for an OLED panel or anyone who found the
  default too grey.
- **Sepia** — a warm cream paper with brown-grey text, rather than the cool blue-white of Light.
- **Ocean, Forest, Dusk, Rose** — four gently tinted darks, leaning blue, green, violet and a
  warm rosé.

The four tinted darks are generated from the contrast-verified Dark palette by rotating the
neutral ramp to a single hue and **preserving every token's lightness** — so the ratios stay
Dark's, and the faintest content token clears 4.5:1 in all four. The tint is deliberately
gentle: a ground you notice, not one that shouts, in keeping with the rest of the app. Under
the hood the appearance moved from a two-value enum to a named-palette scheme; `--theme`,
persistence, the theme switch (now a 4×2 grid) and the ten-language names all followed.

### Eight accent colours

Four to eight: amber, sage, periwinkle and neutral, joined by clay rose, muted sky, soft violet
and muted green — all in the same low-saturation register, because the accent is a wash behind a
selected row and text on a pill, never a full field.

### Fixed — the nine regressions in the 0.9.9 diff

- **The Escape shortcut was wired backwards.** It was meant to stand down while the apply
  overlay is up; instead it turned *on* then (so Escape still cleared the search behind the
  scrim) and off for good when the overlay closed (so Escape stopped clearing the search for
  the rest of the session).
- **A language change wiped three SysInfo fields.** Activation, the last restore point and the
  last update come only from the async probe; re-reading `SysInfo::collect()` on a language
  change blanked them. `SysInfo::Probe::retranslate()` now replays the probe's cached answer
  onto the fresh struct without paying for the run twice.
- **A tweak's Turkish description contradicted its own switch.** The Start-menu-recommendations
  polarity flip updated i18n.json but not the inline Turkish string in catalog.json — and Turkish
  reads that inline string, not the table. Synced.
- **The Ultimate Performance removal check was inverted** — it reported "the plan was not there"
  exactly when the delete had failed. It now samples the plan before deleting, with a distinct
  message for a delete that did not take.
- **A CMake plugin exclusion named a target that does not exist** (`QOpenSSLBackendPlugin`), so it
  did nothing — the real name is `QTlsBackendOpenSSLPlugin`.
- **The theme setters persisted after the identity guard**, so re-picking a value a `--theme`
  flag had set was dropped instead of saved.
- **Right-to-left text was elided from the wrong end**, cutting the start off long Arabic labels.
- **A button press during the silent launch-time update check was swallowed**, leaving the row
  stuck on "Checking…".
- Three stale-comment and dead-code leftovers from 0.9.9's own cleanup.
